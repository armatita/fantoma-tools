Objects

No objects yet

Objects come from Aseprite. The route that keeps colours exact:

  1. Make a palette in the Palettes tab, Export .gpl, and in Aseprite load it with ≡ (above the palette) → Load Palette…
  2. Draw, and tag each animation (Frame → Tags). Each tag becomes a state; a file with no tags becomes one state named after the file.
  3. Link .aseprite… here and pick the file. From then on, every Ctrl+S in Aseprite updates it here within a second — in the Scene too. Canvas only reads the files you pick (Chrome or Edge).
  4. Or the old way: File → Export Sprite Sheet with JSON Data and, under Meta, Tags ticked (Trim off, any layout but Packed), then Import sheet… with the .png and .json together.

Colours must match a palette exactly; if some do not, the import says which and offers to add them — it never guesses a nearest colour.

Tilesets

No tilesets yet

A tileset is drawn in Aseprite on a tilemap layer over a template: a picture of every place a tile can stand. The template is the rule set — each place’s neighbours say which situation its tile is for.

  1. New starter file… writes an Aseprite file with a template (the built-in platformer one, or a picture of yours) and an empty tilemap layer, at the tile size you choose.
  2. In Aseprite, draw on the tiles layer. Where the same tile belongs in two places, place it again from the tileset rather than drawing it twice.
  3. Link tileset… here. Every save then updates this tab: the rules, the checks, and a random level tiled with your art.
Palettes

No palettes yet

A palette is an ordered list of colours. The order matters: a sprite stores positions in the palette, so index 2 must mean the same thing in every palette you might swap in.

Create one with + New, or import a .gpl, .hex or .pal file — Aseprite and Lospec both export them.

Each colour is shown as the panel will show it: cut to RGB565 the way the export does, then expanded back the way the panel driver does. Drag to reorder; the number is the index a sprite stores.
